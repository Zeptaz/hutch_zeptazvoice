## Sinhala recognition and late-tool stall repair — 2026-10-04, branch `integration/voice-crm` (Tevin, integrator)

Found in a real Sinhala browser call on the integrated stack: short Sinhala turns were transcribed as Japanese or Spanish, and replies stalled ("buffering") or never played. Three changes, all in this repository:

- **Transcription language hints.** `input_audio_transcription` now sends `language_codes` (default `si-LK,en-US,ta-IN`, override `GEMINI_LIVE_INPUT_LANGUAGES`) and a small telecom `custom_vocabulary` ("VAS", "HUTCH", "reload", ...). Live A/B with the same synthesized Tamil sentence: without hints "என்னென்னவாஸ்", with hints "என்ன VAS". Gemini 3.1 Live accepted the config.
- **Late tool call no longer discards the grounded reply.** When Gemini's tool call arrived after Voice had already forwarded the transcript, Voice answered it with the saved Resolve result, then dropped Gemini's whole spoken continuation and only requested speech again after that turn finished: the caller heard silence for the length of the discarded answer (measured 8.6–26 s). The continuation after the tool response is grounded in the same Resolve result, so it now streams as the reply. Audio before the tool response is still dropped; caller interruption still revokes it; if the continuation has no audio, the existing speech request/retry path runs.
- **No second concurrent provider read after a timeout.** The speech-timeout and first-audio-timeout paths broke out of the receive loop while a `receive()` was pending and then started another one, so the session died with websockets `ConcurrencyError`. They now keep the pending read. (Harry's unpushed v4 notes describe a fix for the same symptom; reconcile when that lands.)

Verification: Voice suite **75/75** (`python -m pytest -q`); the two new runtime tests fail on the previous `app.py` and pass now. Live signed probe against the integrated Resolve (real grant, v3, synthesized speech, real Gemini Live): before, late-tool turns reached first PCM 9.4 s and 26 s after the Resolve result and one turn ended `speech_unavailable` + `ConcurrencyError`; after, **3 calls × 3 turns, 9/9 spoken, 0 errors**, late-tool first PCM **0.58–0.67 s** after the Resolve result, speech-end to first audio **2.2–3.0 s**. Real Sinhala speech still needs a human retest (no Sinhala synthetic voice available). Open: Gemini reads long Resolve replies almost in full (a 1,066-character reply played ~28 s) despite the two-sentence rule.

## Live speech latency change — 2026-10-04

The previous exact `speech_text`/output-transcript gate withheld all Gemini PCM until the whole reply completed and matched. This Voice branch now streams valid PCM immediately from the first frame, without an approved-text buffer, output-transcript comparison or local fallback TTS. Each Resolve result supplies a per-turn Gemini Live session memory snapshot containing standing rules, the latest canonical reply, case ID, operation status and proposal.
